## Add the server (OAuth)

```bash
codex mcp add adsmcp --url https://mcp.adsmcp.si/mcp
```

Codex signs in to MCP servers with OAuth through a `localhost` callback, which ADSMCP accepts, so no API key is needed.

## Or use an API key

Create an API key on [API Tokens](https://adsmcp.si/dashboard/api-tokens) (it starts with `sk_live_`). Keep it in an environment variable, never in a chat message. Add ADSMCP to `~/.codex/config.toml` and keep the key in an environment variable:

```toml
[mcp_servers.adsmcp]
url = "https://mcp.adsmcp.si/mcp"
bearer_token_env_var = "ADSMCP_API_KEY"
```

```bash
export ADSMCP_API_KEY=sk_live_...
```

If the client can only start local (STDIO) servers, use the [STDIO proxy](/mcp-setup#stdio-proxy) instead.

## Agent Pack (optional)

From a checkout of the ADSMCP repository:

```bash
node ./bin/adsmcp-agent.mjs install --client=codex
```

It copies the performance-marketing agent, the workflow skills and the ADSMCP [skills](/agent-skills) into `~/.agents`. See [Workflows](/workflows).

## After you connect

1. Ask your first question, for example: *"Which campaigns spent money last week without a single conversion?"*
2. If you have not connected an ad account yet, the reply contains a link to [Connections](https://adsmcp.si/dashboard/connections). Connect the platform there and ask again.
3. Ask for a read, such as last week's performance, before asking for changes.

Every change the client proposes is staged as a pending action. Approve or reject it on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page; the client cannot approve it. The client runs on your own AI model and plan, and each ADSMCP tool call counts against your [ADSMCP plan](/pricing).
