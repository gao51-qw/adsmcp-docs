The REST API runs the same tools as the [MCP server](/mcp), over plain HTTP. Use it from scripts, schedulers, or your own backend.

| | |
| :- | :- |
| **Base URL** | `https://mcp.adsmcp.si` |
| **Run a tool** | `POST /api/v1/tools/{tool}/execute` |
| **List tools** | `GET /api/v1/tools` |
| **OpenAPI spec** | `GET /api/v1/openapi.json` (the same document as this reference) |
| **Auth** | `Authorization: Bearer sk_live_...` from [API Tokens](https://adsmcp.si/dashboard/api-tokens) |

## Request

```bash
curl -X POST https://mcp.adsmcp.si/api/v1/tools/get_connections_status/execute \
  -H "Authorization: Bearer $ADSMCP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"platform": "meta", "arguments": {}}'
```

- `arguments` is the tool's input. Each tool page lists the exact fields, taken from the tool's input schema in code.
- `platform` is the tool's platform (`google`, `meta`, `tiktok`, `amazon`, `linkedin`, `chatgpt`, `google_analytics`, `klaviyo`). Send it as shown on the tool page.
- `Idempotency-Key` (optional header): a repeat of the same key while the first request is still running returns `409`.
- Pass every account, campaign, ad group, ad and creative id as a string.

## Response

Every call returns the same envelope:

```json
{
  "ok": true,
  "platform": "meta",
  "tool": "get_connections_status",
  "data": {},
  "error": null,
  "mcp_response": {}
}
```

On failure `ok` is `false` and `error` holds `code`, `message` and `details`. `401` means the token is missing or invalid. Calls over your plan's allowance are refused with `quota_exceeded` (see [Pricing](/pricing)).

## Reads and changes

- **Reads** run right away and change nothing.
- **Changes** never run on the call. ADSMCP checks the arguments and stages the change as a pending action. A person approves it on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page; only then does it run. The API can list pending actions (`list_pending_actions`) and reject one (`manage_action`), but it cannot approve, execute or retry anything.
- New campaigns, ad groups, ads and creatives are created paused or as drafts.
- Budget changes and enables are checked against your [spend cap](/safety#spend-cap) when the approved change runs.
- `remove_*` and `delete_*` tools need `confirm_delete: true`, and are then staged for approval like any other change.

See [Safety model](/safety) and [Approvals](/approvals).

## Older tool names

Some tools also accept an older name (for example `list_meta_campaigns` runs `get_campaigns`). The tool page lists them under **Also accepted as**, and pages for old names redirect to the tool.

## Not supported yet

Pages in the **Not supported yet** group describe tools that ADSMCP does not have. They are kept so old links still work, and each one points to the tools to use instead. They are not in the OpenAPI spec.

## Regenerating this reference

The reference is built by `scripts/generate-api-reference.mjs` in the docs repository from the ADSMCP code (`services/mcp/src/openapi-spec.mjs`). Operator-only governance tools are not part of the public catalog and have no page.
