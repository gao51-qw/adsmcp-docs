Scheduled detection is done by the Watch Agent, by metric monitors, and by automation rules saved for scheduled evaluation. Other rules are checked on demand: a rule is compared with a metric value only when `test_automation_rule` is called. A pause, budget change, or campaign enable still waits for approval.

## Automation rules

Rules live at [Automation Rules](https://adsmcp.si/dashboard/automation-rules).

1. Read the thresholds and exclusions in `STRATEGY.md`.
2. Call `get_connections_status`.
3. Review what already exists with `list_automation_rules`.
4. Draft a rule with `create_automation_rule` only after you have seen the trigger, the action, and the fact that the action stays approval-gated.
5. Run `test_automation_rule` with the current `metric_value`. A saved rule has status `active` and, unless you ask otherwise, `evaluation` `on_demand`: ADSMCP does not read live metrics for it or check it on a timer.
6. To have ADSMCP check a rule by itself, save it with `evaluation` `scheduled`, or call `manage_automation_rule` with `schedule`. See [Scheduled rules](#scheduled-rules).
7. Pause, resume, schedule, unschedule, or delete a rule with `manage_automation_rule`.

Rules are stored per user. You see and test only your own rules, and you can keep up to 100. A rule that only notifies changes nothing. A rule whose action would change spend stages that change in the approval queue when it triggers.

## Rule fields

`create_automation_rule` requires `name`, `platform`, `metric`, `operator`, `threshold`, and `action`. A saved rule has status `active`.

| Field | Values |
| --- | --- |
| `operator` | `gt`, `gte`, `lt`, `lte`, `eq` |
| `action` | `notify`, `pause_campaign`, `pause_ad_set`, `update_budget` |
| `lookback_window` | Stored as text. The omitted value is `7d`. |
| `cooldown_minutes` | The omitted value is 60. The stored value is at least 1 and at most 10080. |
| `evaluation` | `on_demand` (the omitted value) or `scheduled`. |
| `action_arguments` | Object copied onto a later pending action (for example `campaign_id`, `ad_set_id`, `daily_budget`). At most 4,000 characters of JSON. |

An unsupported operator, an unsupported action, a missing name, platform, or metric, or a non-numeric threshold returns `invalid_automation_rule` and `validation_errors`. The rule stays unsaved. The 101st rule returns `automation_rule_limit_reached`.

`list_automation_rules` accepts optional `platform` and `status` (`active` or `paused`) and returns only your own rules.

`manage_automation_rule` takes `rule_id` and an `action` of `pause`, `resume`, `schedule`, `unschedule`, or `delete`. A rule that is not yours returns `automation_rule_not_found`.

`test_automation_rule` loads your own rule by `rule_id`, or uses the `rule` object on the call. A missing rule, or a rule that belongs to someone else, returns `automation_rule_not_found`. A paused rule returns `automation_rule_paused`. The comparison uses `metric_value` from the call and the rule threshold. Live account metrics stay unread.

When the comparison matches and the action is `notify`, the result is `triggered: true` and `pending_action` is null. Any other matching action stages a `pending_approval` action with risk level `high`. `update_budget` sets `tool_name` to `update_campaign_budget`, with the budget in major currency units. Nothing runs until a person approves it, on the dashboard or in the confirm dialog of an allowed AI client.

## Scheduled rules

A rule saved with `evaluation` `scheduled` is checked about once an hour. ADSMCP reads the metric of the rule's own campaign or ad set from Meta over the rule's `lookback_window` and compares it with the threshold.

A rule can be scheduled only when ADSMCP can read it:

| Requirement | Refusal when missing |
| --- | --- |
| `platform` is `meta` | `schedule_platform_not_supported` |
| `metric` is `cpa`, `roas`, `ctr`, `cpc`, `spend`, or `conversions` | `schedule_metric_not_supported` |
| `action_arguments` has a `campaign_id`, or an `ad_set_id` for `pause_ad_set` | `schedule_target_required` |

When a scheduled rule triggers:

- A `notify` rule emails you. Nothing is changed or staged.
- A rule with any other action stages that change as a pending action and emails you. It runs only after a person approves it, on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page or in the confirm dialog of an [allowed AI client](/approvals#approving-in-your-ai-client).
- The rule then waits its `cooldown_minutes`, and at least 6 hours, before it can trigger again.

A metric that cannot be read never triggers a rule. A scheduled rule shows `last_evaluated_at`, `last_triggered_at`, `last_metric_value`, and `last_result`: `within_threshold`, `triggered_notified`, `triggered_staged`, `draft_refused:<reason>`, or the reason the metric could not be read (for example `no_data` or `credentials_missing`).

## Watch Agent

Watch Agent is an admin screen at [Watch Agent](https://adsmcp.si/dashboard/watch-agent). The runtime is built for a recurring 15-minute scan. It looks for KPI breaches such as CPA above target, ROAS below target, budget pacing problems, and creative fatigue.

What it does with a finding:

- Record a signal you can review on the Watch Agent page.
- Open a Pending Action when the suggested fix would change spend or delivery.
- Send a notification for a degraded check, an error, or a recovery.

It does not enable a campaign or change a budget by itself. If the agent runtime is unavailable, monitoring degrades instead of failing open into writes.

Metric monitors on [Monitors & Alerts](https://adsmcp.si/dashboard/monitors) follow the same rule: read, notify, and queue. Nothing runs until a person approves it, on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page or in the confirm dialog of an [allowed AI client](/approvals#approving-in-your-ai-client); an AI client can list or reject a pending action but never approve it.
