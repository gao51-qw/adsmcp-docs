A read runs right away. A change — create, pause, enable, budget, bid, status, or delete — never runs on the call. It becomes a **pending action**, and nothing happens in your ad account until a person approves it on the dashboard.

## Where to approve

Open [Ad Ops → Approvals](https://adsmcp.si/dashboard/approvals). Each pending action shows the tool, the platform, the account, the arguments and a risk level.

- **Approve & Execute** runs the change with the stored arguments.
- **Reject** discards it. You can add a reason and save it as a [Knowledge Studio](/knowledge-studio) draft so the agent learns from it.

Only a signed-in person can approve. This is true whatever the tool arguments say: `execution_mode` and similar fields never skip the queue.

## What an AI client can do

| Tool | What it does over MCP / REST |
| --- | --- |
| `list_pending_actions` | List your pending actions (view only). |
| `manage_action` | `decision: "view"` shows one action; `decision: "reject"` rejects it. `approve` is refused with `approval_requires_dashboard`. |
| `list_execution_queue` | List approved actions and their run status (view only). |
| `list_dead_letter_queue` | List actions whose run failed and was set aside. |
| `resolve_dead_letter_action` | Close a dead-letter item as `resolved` or `rolled_back`. It never runs or re-queues it. |
| `get_action_audit` | Read the history of proposals, approvals and runs. |
| `execute_queued_action`, `retry_queued_action`, `resume_workflow_after_approval` | Always refused with `approval_requires_dashboard`. |

## What happens when you approve

1. The stored change runs once, exactly as approved.
2. Creates are made paused or as drafts, so they cannot spend yet.
3. Budget changes and enables are checked against your [spend cap](/safety#spend-cap) first. Over the cap, or if a budget cannot be read, the change is refused and nothing is sent to the platform.
4. Deletes were only staged if the call carried `confirm_delete: true`; once approved they cannot be undone.
5. If the platform rejects the change, the failure is shown on the item. Nothing retries automatically. Fix the cause and stage a corrected change, which needs a new approval.

Admins can follow every approved action on the [Execution Queue](https://adsmcp.si/dashboard/execution-queue) page (view only) and investigate failures on [Diagnostics](https://adsmcp.si/dashboard/diagnostics) with `get_recent_errors`, `get_request_trace` and `search_service_events`.

## Monitors, rules and schedules

`test_monitor`, `test_automation_rule` and `optimize_budget` can stage pending actions too. They land in the same queue and wait for the same approval. See [Alerts](/alerts) and [Automation](/automation).
