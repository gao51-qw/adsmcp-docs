ChatGPT Ads are ads that run inside ChatGPT. ADSMCP reads them and stages changes: new campaigns, ad groups and ads (created paused), creative uploads, custom audiences, pixels and conversion settings, and changes to existing objects. (Using ChatGPT as your AI client is separate; see [ChatGPT](/ai-clients/chatgpt).)

## Connect

On [Connections](https://adsmcp.si/dashboard/connections), paste the ChatGPT Ads API key for each ad account you want to connect. Then call `get_connections_status` and `list_chatgpt_accounts`. Pass the account id (`adacct_...`) on later calls.

## What you can do

- **Report:** account performance, insights by level (with country or device segments, filters and sorting) and conversion insights.
- **Read structure:** campaigns, ad groups and ads.
- **Read setup:** location lookup (`chatgpt_geo_lookup`), custom audiences and their membership operations, pixels (with the snippet for your page's `<head>`), event settings, recent pixel events and the conversions config.
- **Test:** `test_chatgpt_conversion` sends one event with `validate_only: true`. OpenAI checks it but does not save it, so it runs right away without approval.
- **Change (approval):**
  - create campaigns, ad groups and ads (always created paused);
  - `launch_chatgpt_ad`: one approval that uploads the image, then creates the campaign, ad group and ad, in that order. If a step fails it stops and reports the ids created so far;
  - upload creatives; change an ad's name and chat card (title, body, destination URL, image);
  - create, merge and archive custom audiences; add, remove or replace members; cancel or resume a membership operation;
  - create pixels, event settings and a Conversions API key, set the conversions config and send conversion events;
  - pause, resume and archive campaigns, ad groups and ads; change a campaign budget (normal currency units, at least 1) and an ad group's max bid;
  - change a campaign's start and end time, targeting (locations, audiences, surfaces) and conversion goals, and an ad group's bid strategy and audience bid multipliers. When the change runs, ADSMCP checks the object still looks as it did at staging, and checks afterwards that OpenAI applied it.

How some inputs work:

- **Locations:** pass location ids or country codes. Look them up with `chatgpt_geo_lookup` first; free text is not accepted.
- **Images:** an image URL is fetched by ADSMCP with private and internal addresses blocked. The image must be at least 640×640, and if it changes between staging and approval, the approved run is refused.
- **Customer identifiers** (emails, phones, names, external ids) are SHA-256 hashed when the change is staged. The pending action and the approval card show only hashes and counts. Identifiers OpenAI needs unhashed (IP address, user agent, GAID, city, region, postal code) are refused; upload those to OpenAI yourself.
- **Conversions API key:** stored only in ADSMCP's vault. The key is shown once, to the person who approves its creation on the dashboard; it is never returned to your AI client.
- **Spend cap:** creating a campaign or launching an ad is checked against your spend cap as if the new campaign were active. Edits that can raise spend (a later or removed end date, broader targeting, an earlier start, a higher bid or multiplier, a strategy change) are checked too.

Not available yet: changing an ad group's schedule or targeting, or its bidding type (OpenAI's API does not offer these).

## Changes need your approval

Every change below is staged as a pending action. Nothing changes in the account until a person approves it on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page; your AI client can view or reject it, never approve it. When an approved change runs, new objects are created paused or as drafts, budget changes and enables are checked against your [spend cap](/safety#spend-cap), and a failure is not retried. `remove_*`, `delete_*` and `archive_*` tools (and their `batch_` forms) also need `confirm_delete: true`.
