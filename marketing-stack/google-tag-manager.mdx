ADSMCP reads the Google Tag Manager accounts your Google login can open, so your AI client can check whether a pixel or conversion tag is really installed. It never changes a container.

## Connect

1. Open [Connections](https://adsmcp.si/dashboard/connections) and find **Google integrations**.
2. Choose **Tag Manager → Connect** and sign in with Google. ADSMCP asks for the read-only Tag Manager permission (`tagmanager.readonly`) and nothing else; if you untick it, the connection is refused.
3. Every GTM account the login can read is found and listed. Containers and workspaces are read live when a tool runs.
4. If exactly one account is found it is enabled automatically. With more, choose which accounts your AI may use in the **Active accounts** card on Connections (any number, no plan cap).

Reconnecting keeps your choices; an account found for the first time starts not enabled. A login with more than 500 accounts is refused. Tools see enabled accounts only: naming an account that is not enabled, or calling while none is enabled, returns `not_enabled` with a link to choose. Tag Manager does not count toward the [active-account cap](/accounts#active-accounts).

## Tools

All tools are reads and work with a read-only API key. Each call counts as one [tool call](/pricing#what-a-tool-call-is).

| Step | Tools |
| --- | --- |
| Find the container | `list_gtm_accounts`, `list_gtm_containers`, `list_gtm_workspaces` |
| Read what is set up | `get_gtm_tags`, `get_gtm_tag`, `get_gtm_triggers`, `get_gtm_variables` |
| Pending work | `get_gtm_workspace_status` (changes in a workspace compared with the latest version, and merge conflicts) |
| Published versions | `list_gtm_versions`, `get_gtm_version` |

Tags, triggers and variables are read from a workspace draft by default. Pass `live: true` to read the **published** version instead: that is the one to use when you ask "is my Meta pixel / Google Ads conversion tag installed?".

`google_tag_manager` is a router for the same reads. Its list also names write actions (create or change tags, change variables, publish a version) as `available: false`; calling them returns `not_available` and nothing is sent.

If there is only one account, container or workspace you can leave it out. With several, the call returns `ambiguous_gtm_account`, `ambiguous_gtm_container` or `ambiguous_gtm_workspace` with the choices, one level at a time: that is not a connection problem, pick one and call again.

## REST example

```bash
curl -X POST https://mcp.adsmcp.si/api/v1/tools/get_gtm_tags/execute \
  -H "Authorization: Bearer $ADSMCP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"platform": "google_tag_manager", "arguments": {"live": true}}'
```

Over MCP the reads are on the `google_tag_manager_read` router, or call each tool by name. See the [API reference](/api-reference/google-tag-manager/google-tag-manager) for every argument.
