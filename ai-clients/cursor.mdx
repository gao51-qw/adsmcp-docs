## Setup

**Install from Customize (Recommended)**

**1. Open Customize**

In Cursor, open **Customize** in the sidebar. This is where every plugin, MCP server, rule, and skill is managed.

You need Cursor v2.4+ (for subagent support) and an ADSMCP account — [free to start](https://adsmcp.si), no card.

**2. Search for ADSMCP**

Search for **adsmcp**, or click **Browse Marketplace** to see the full catalog. Pick **ADSMCP**, created by ADSMCP and marked **Verified by Cursor**.

![Cursor Customize page with a marketplace search returning the ADSMCP plugin, next to the Browse Marketplace button](/images/xQY-jlSRqCTgZmaL/images/cursor/customize-search.png)

Customize — search the marketplace without leaving Cursor

**3. Install it**

Select **Install** and choose a scope:

* **User** — ADSMCP is available in every Cursor project. Pick this if you manage ads regularly.
* **Project** — ADSMCP is available only in this folder. Pick this when you're working in one client's workspace.

**4. Sign in to ADSMCP**

The first tool call opens ADSMCP's sign-in page in your browser. Sign in, authorize access, and return to Cursor. Authentication is OAuth — there is no API key or client secret to paste anywhere.

Then connect the ad accounts you want to manage at [adsmcp.com/connections](https://adsmcp.si/connections).

**5. Set up your brand workspace**

Open your brand folder in Cursor, switch to **Agent mode** (not Ask or Edit), and say:

```
set up my brand workspace
```

The agent checks your connected accounts, scans the folder for brand docs, pulls a live performance snapshot, and proposes a `BRAND.md`. It asks before writing any file. If it doesn't trigger on its own, run `/adsmcp-setup`.

## How the Rules Change Your Workflow

The plugin ships two rules that run automatically. You can see them under **Rules** in Customize and toggle each between **Always**, **Agent Decides**, and **Manual**.

**`brand-workspace`** loads context before the agent answers: `BRAND.md` for voice, audiences, budgets and KPI targets, `STRATEGY.md` for binding directives, and past decisions from memory.

**`use-adsmcp`** enforces the order of operations. Here's the difference it makes:

**Without the rule** — you say *"Create a Google Ads campaign for running shoes"* and the agent calls `create_search_campaign` with generic parameters. It fails: no keyword research, no validated assets.

**With the rule** — the same sentence triggers the full workflow:

1. `get_connections_status` — verify you're managing the right account
2. `research_keywords` on "running shoes" seeds, with real CPC data
3. Shows you the keyword and CPC data before going further
4. `discover_existing_assets` — reuse images and headlines you already have
5. `validate_and_prepare_assets` — check them against Google's requirements
6. `create_search_campaign` with validated data
7. **Asks for your confirmation** before anything is created

One vague prompt becomes a complete, validated workflow. Nothing launches without your approval.

## Safety

* **Campaigns are created paused.** Review before they spend.
* **Spend-affecting writes need your approval.** Campaign creation, budget changes, and bid changes all stop for confirmation.
* **Read before write.** Connection check, then research, then validate, then create.
* **Results are read back.** The agent re-reads what it created before reporting success.
* **Campaigns are never deleted automatically.**
* **No credentials in the plugin.** OAuth 2.1 with PKCE; your ad platform credentials stay server-side with ADSMCP. The marketplace build ships no hooks, executables, or bundled server code, and talks only to `https://mcp.adsmcp.si/mcp`.

## Troubleshooting

| Problem | Solution |
| - | - |
| Can't find ADSMCP in Customize | Search `adsmcp` (lowercase, one word). Update Cursor if the Marketplace section is missing. |
| "Disabled by team admin" | Your Cursor team admin controls which marketplace plugins are available. Ask them to enable ADSMCP. |
| Tools don't appear after install | Check **Customize → MCP** and make sure `adsmcp` is toggled on. A disabled server doesn't load. |
| Sign-in window doesn't open | Check your browser's pop-up blocker, then restart Cursor. |
| Authentication failed | Toggle the `adsmcp` MCP server off and on in Customize to re-run OAuth. |
| No ad platforms connected | Connect them at [adsmcp.com/connections](https://adsmcp.si/connections). |
| Skills not matching | Confirm they're listed under **Agent Decides** in Customize. Force one with `/adsmcp-setup` or `/adsmcp-performance-review`. |
| Subagent not triggering | You must be in **Agent mode** — not Ask or Edit. |
| No data returned | Check that the account has active campaigns, then try a longer lookback (60 or 90 days). |
| Rate limit hit | See [pricing](/knowledge-base/pricing) for your plan's tool call allowance. |

## FAQ

> **Should I install at user scope or project scope?**
>
> **User scope** makes ADSMCP available in every Cursor project. Pick this if you manage ads regularly.
>
> **Project scope** limits it to one folder. Pick this when you're in a client's codebase and want ad tools only there, or when you keep a separate folder per brand.

> **Do I need to add ADSMCP as an MCP server or edit mcp.json?**
>
> No. ADSMCP is a **Verified by Cursor** marketplace plugin, and installing it adds the `adsmcp` MCP server for you, along with the subagent, skills, and rules. If you added `https://mcp.adsmcp.si/mcp` to `mcp.json` or under **Customize → MCP** before the plugin existed, remove that entry so Cursor doesn't load two copies of every tool.

> **What happened to the install script?**
>
> It's retired. The `bash <(curl ...)` installer predates the Cursor Marketplace — it copied skills, rules, and an agent into `~/.cursor/` by hand. The marketplace install does the same thing in one click, updates itself, and is reviewed by Cursor before each release. If you ran the old script, uninstall the copied files from `~/.cursor/skills/`, `~/.cursor/agents/`, and `~/.cursor/rules/` so they don't duplicate the plugin's.

> **Can I use ADSMCP with Cursor Composer?**
>
> Yes. Composer has full access to ADSMCP tools. You can ask it to analyze campaigns, generate a report, and save the output as markdown in your project — all in one flow.

> **Where does the plugin keep brand context?**
>
> `BRAND.md` and `STRATEGY.md` live in your project root, so they're yours to read and edit. Past decisions go in `.cursor/memory/performance-marketing-agent/MEMORY.md`.
>
> If you already have a `BRAND.md` that isn't an ADSMCP workspace, the agent leaves it alone and says so.

> **How much does ADSMCP cost?**
>
> Pricing is based on tool calls, not ad spend, and it's the same across every AI client. See [pricing and plans](/knowledge-base/pricing).

> **Can I manage multiple ad accounts?**
>
> Yes. Connect multiple Google Ads accounts, multiple Meta Business Managers, and so on. Use `switch_primary_account` to change which one you're managing, or name the account ID in your prompt. See [multi-account](/knowledge-base/multi-account).
