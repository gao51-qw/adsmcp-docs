## Option 1: MCP server only

```bash
claude mcp add --transport http adsmcp https://mcp.adsmcp.si/mcp
```

Then run `/mcp` in Claude Code, choose `adsmcp` and authenticate. Claude Code signs in with OAuth through a `localhost` callback, so no API key is needed.

To use an API key instead:

```bash
claude mcp add --transport http adsmcp https://mcp.adsmcp.si/mcp --header "Authorization: Bearer $ADSMCP_API_KEY"
```

## Option 2: the `adsmcp` plugin

The plugin adds the MCP server plus five skills and an agent. From a checkout of the ADSMCP repository:

```text
/plugin marketplace add /path/to/ADSMCP
/plugin install adsmcp@adsmcp-marketplace
```

| Command | What it does |
| --- | --- |
| `/adsmcp:setup` | Checks context files and connections, and says what to run next. |
| `/adsmcp:performance-review` | Scorecard against your targets, with the top three recommendations. |
| `/adsmcp:write-ad-copy` | Copy guidelines from your brand context; your model writes the variants. |
| `/adsmcp:wasted-spend` | Ranks spend that misses your targets; fixes become pending actions. |
| `/adsmcp:campaign` | Validates and stages a paused campaign. |

The plugin also installs the `performance-marketing-agent` subagent. See [Workflows](/workflows).

The installer is an alternative to the plugin: `node ./bin/adsmcp-agent.mjs install --client=claude` from the same checkout copies the agent, skills and commands into `~/.claude`.

## After you connect

1. Ask: *"Call get_connections_status and tell me which ad platforms are connected. Do not change anything."*
2. If a platform is missing, connect it on [Connections](https://adsmcp.si/dashboard/connections).
3. Ask for a read, such as last week's performance, before asking for changes.

Every change the client proposes is staged as a pending action. Approve or reject it on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page; the client cannot approve it. The client runs on your own AI model and plan, and each ADSMCP tool call counts against your [ADSMCP plan](/pricing).
