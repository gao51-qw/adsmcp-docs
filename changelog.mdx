**October 21, 2026**

ChatGPT users: add ADSMCP as a custom MCP server. It works on every plan, including Free

## In ChatGPT, Connect ADSMCP Directly

The ADSMCP plugin in ChatGPT's **Plugins** directory is having issues, and it was already missing Amazon Ads, ChatGPT Ads, Google Analytics, and Google Search Console. The ChatGPT setup guide now leads with the path that works: add ADSMCP as a **custom MCP server**.

You get every tool the day it ships, on the same ADSMCP account you already use. If you installed the plugin, disconnect it under **Settings → Plugins** so ChatGPT doesn't pick it.

**October 19, 2026**

Amazon reports stay inside the ad product you ask for, and Meta reports and campaign flows stop saying things that aren't true

## Reports That Say What The Data Says

**Amazon: a Sponsored Brands report is now only Sponsored Brands.** Sponsored Products, Brands, and Display share one analytics store, and campaign, search-term, targeting, product, ad-group, and placement reads were filtering by account and date only. Ask for Sponsored Brands and you got Display and Products rows too, with account-wide totals. Each read now returns the product you asked for. `ad_product` takes `SP`, `SB`, `SD` or the full names; anything else is rejected with an error instead of defaulting to Sponsored Products.

**Meta performance and audience reads no longer mislead.**

* A date range entirely after your last delivery used to say your range was "before any recorded activity." It now says there was no delivery in the period and gives the date of the most recent activity.
* The CPC and CPA lines in the written summary of `get_meta_campaign_performance` now match the table. The summary line could read \$0.00 while the table had the real figure.
* `get_meta_audience_insights` no longer reports "performing steadily" when there is nothing to rank. It says either that there was no delivery, or that impressions delivered but Meta couldn't resolve them to an age or gender segment.
* `validate_catalog_readiness` reports **limited** retargeting when the pixel fires only `InitiateCheckout` or `AddToWishlist`. Only `ViewContent` or `AddToCart` counts as ready.

**Meta campaign flows.** `validate_and_prepare_meta_assets` on a single image used to print "Asset Bundle ID: None" and a next step that passed `"None"` to `create_meta_image_campaign`. It now returns the image hash and points you to `existing_image_hash`. Carousel cards take the same hash under `image_hash`. `resume_meta_campaign` no longer claims delivery has resumed: it sets the campaign to ACTIVE, and delivery needs an active ad set and ad too.

**October 19, 2026**

Remove Google radius targets by ID, see full radius addresses, and Meta ad-set targeting edits no longer wipe what you didn't send

## Take A Radius Back Out, And Edit Meta Targeting Without Wiping It

**Google radius targeting now works in both directions.** `remove_campaign_proximity` is the opposite of `add_campaign_proximity`: ask your assistant to stop targeting within a set distance of an address and it removes that radius. It works from the **Criterion ID** that `get_campaign_targeting` now shows beside each radius and location. It only ever removes radius targets, so an ID that belongs to a location or keyword is skipped and reported instead of deleted.

`get_campaign_targeting` also reads radius targets properly. A street address used to show as a bare country code with no units. It now shows the full address and miles or kilometers. Targeting reads refresh within a minute, and a change you make shows on the next read.

**Meta partial targeting edits keep the rest.** Meta replaces the whole targeting spec on every edit, so changing only an age range on `update_meta_ad_set` or `update_meta_catalog_ad_set` used to drop locations, interests, and everything else you didn't resend. Edits now merge onto the ad set's current targeting. Send only the keys you want to change; to clear a key, send it empty.

**October 2, 2026**

Connecting an ad account mid-setup no longer loses the hand-off back to the Authorize screen your AI client is waiting on

## Connect An Ad Account Mid-Setup, Still Land On Authorize

Setting up from ChatGPT, Claude, or any other client ends on ADSMCP's **Authorize** screen, and most people connect their first ad account on the way there. That connect opens the ad platform's own sign-in in a pop-up — and on mobile Chrome and desktop Safari, that pop-up often comes back without a link to the tab that opened it. ADSMCP was holding the pending authorization in that one tab, so the return had nowhere to go: setup finished, you landed on your account page, and the client that sent you there was never connected.

The authorization now travels with you instead of sitting in one tab. It rides on the return address ADSMCP hands the ad platform — Google, Meta, TikTok, LinkedIn alike — so an opener-less pop-up return still knows to finish the hand-off. The plan step in the middle of setup keeps it the same way.

**And if you already finished setup in another tab,** returning to the tab that still carries the authorization forwards you straight to the **Authorize** screen instead of showing you your account page. Only an authorization on the address itself counts, so an ordinary visit to the setup page can never replay an old one.

**September 30, 2026**

The ADSMCP Authorize screen now shows it's working, ignores a second click, and restarts a lapsed sign-in instead of showing an error page

## You Clicked Authorize. Now The Page Says So.

Every client's setup ends on the same screen: ADSMCP's **Authorize** page, where you grant your assistant access. You clicked **Authorize** and the page sat there, apparently unchanged, for a couple of seconds while your assistant's callback loaded — and the button was already outlined when the page opened, so it looked selected before you touched it. The natural response is to click again, which sent a second approval for a connection that had already been approved.

The screen now answers the first click. The button turns into a spinner reading **Connecting…**, with a line underneath naming the app you're connecting and telling you that you'll be taken back automatically. Clicks after the first do nothing, and so does Enter — the first click is the one that counts, so a second one can't send a second approval. Nothing is focused when the page loads.

If the hand-off takes longer than usual, the screen says so rather than leaving you to guess. Around eight seconds it tells you it's still connecting and to keep the window open; around twenty it tells you to press **Authorize** again if your client never opened. Desktop apps hand off differently — they open over this page instead of replacing it — so those end on **Sent ✓** and tell you that you can close the window once the app comes up.

**A lapsed sign-in no longer dead-ends.** Leave the Authorize screen open long enough and your ADSMCP sign-in expires behind it. Clicking **Authorize** then used to land you on a bare error page with no way forward. Now it sends you back through sign-in and returns you to the same Authorize screen with your request intact — finish signing in, click **Authorize**, and you're connected. No access is granted on that path, and the expired sign-in isn't carried through it.

**September 28, 2026**

Sellers can read the brand entity ID Sponsored Brands requires, instead of hunting for it outside ADSMCP

## Sponsored Brands Asks Sellers For A Brand ID. Now You Can Just Read It.

Creating a Sponsored Brands campaign on a **seller** account means passing a `brand_entity_id`, and ADSMCP had no way to tell you what yours was. Either you already had it written down, or the campaign didn't get created. Vendor accounts were never affected — they can usually leave the field empty.

**`list_amazon_brands`** reads the Brand Registry entities on your Amazon profile and returns each one's `brandEntityId`, next to its `brandId` and its registered brand name. Read-only. Ask for your brands, take the ID, create the campaign.

Two things worth knowing. Sponsored Brands wants the **`brandEntityId`** — the long one starting with `ENTITY` — not the shorter `brandId` sitting beside it. And each advertiser profile carries its own, so a brand you sell under in the UK and in the US has a different ID in each marketplace; ask against the profile you're about to advertise on.

It covers creative assets too — `upload_amazon_asset` takes the same ID from sellers. And when Amazon rejects a Sponsored Brands campaign over a brand problem, the error now names this tool rather than leaving you to work out which field it meant.

**September 27, 2026**

Performance Max finally answers 'what did it spend on?', and negative keyword lists become reusable across campaigns

## Performance Max Will Tell You What It Spent On

Ask for the search terms on a Performance Max campaign and the answer used to be **"No search term data"** — which read like Google was hiding them. It wasn't. Google keeps PMax queries in a different place than Search and Shopping queries, and ADSMCP was only reading the latter. Two tools now read the PMax side.

**`analyze_pmax_search_terms`** returns every query the campaign matched, one row each, with cost, clicks, impressions, conversions, conversion value, CTR, and CPC. It opens with a summary across the whole window — how many terms, total cost, total conversions, and how many terms recorded no conversions along with what they cost. Those are facts, not a verdict: a query with nothing attributed may be upper-funnel or tracked elsewhere, and that call is yours.

**`analyze_pmax_search_categories`** reads Google's own grouping of those queries into search categories, so you can see the shape of demand — which themes convert — without reading ten thousand individual terms. Google's residual **(Other search terms)** bucket comes back labelled rather than silently folded into a total.

Both take a lookback of 7, 30, 60, 90, or 120 days, sort on any metric they return, and take a free-text filter so "show me everything with *free* in it" is one call. Results are ranked by cost first, so the terms worth your attention are on the first screen — paging is capped on purpose rather than inviting a walk through the long tail. Money renders in your ad account's own currency.

## One Negative Keyword List, Every Campaign

`add_negative_keywords` blocks a term on one campaign. Blocking the same twenty terms across fifteen campaigns meant fifteen calls, and adding a sixteenth term later meant fifteen more.

Five new tools bring Google's shared negative keyword lists to the agent: **`create_negative_keyword_list`** to start one, **`add_negative_keywords_to_list`** to fill it (each term `EXACT`, `PHRASE`, or `BROAD`), **`attach_negative_keyword_list_to_campaign`** to put it to work, and **`list_negative_keyword_lists`** / **`get_negative_keyword_list`** to read back what you have — the first of those reports each list's keyword count and how many campaigns it's attached to.

Add a term to the list and every campaign carrying it blocks the term at once. Detaching a list from one campaign leaves it intact everywhere else.

**September 27, 2026**

Meta engagement campaigns stop failing on a performance goal you never picked

## An Engagement Campaign That Actually Gets Created

Asking for a Meta engagement campaign — the objective that buys reactions, comments, shares, and saves on a Page post — failed at creation every time, with a rejection that blamed a setting you never chose:

> Performance goal isn't available: You can't use the selected performance goal with your campaign objective

Meta wants an engagement ad set to declare **where** the engagement happens. ADSMCP sent the performance goal and the Page, but left the destination blank, and Meta refuses that pairing at creation — so the campaign never existed. It now sets the destination to the post itself, which is the one Meta accepts for post engagement.

Every create path that can build an engagement ad set is covered: **`create_meta_image_campaign`**, **`create_meta_video_campaign`**, **`create_meta_carousel_campaign`**, and **`add_meta_ad_set`**.

Nothing else moved. Pass `destination_type` yourself and your value still wins. Campaigns that send people into WhatsApp, Messenger, or Instagram Direct keep their own destination. Traffic, leads, sales, and awareness campaigns were never affected and are unchanged.

**September 23, 2026**

Google Analytics, Search Console and Tag Manager stop guessing which property, site or container you meant, and ask instead

## One Google Login, Many Properties — And No More Guessing Which

Connecting Google Analytics hands ADSMCP one Google login, and that login usually reaches more than one thing: a dozen GA4 properties, several verified Search Console sites, a Tag Manager account with containers under it. Ask for "last week's sessions" without saying which property and the agent had to pick one. A wrong read gave you another site's numbers with no hint they were the wrong site's. A wrong write — a tag created in the wrong container — quietly changed tracking on a live website.

The agent now asks. Call an action that operates on a specific property, site, or container without naming one, and ADSMCP pulls the real labelled list off your connection and hands it back for you to choose from:

```
You have 28 properties connected for Google Analytics on jane@agency.com.
This is NOT a connection problem — do not reconnect. Tell me which one —
a single property, a few, or all of them — then call again.
```

Picking is part of the conversation, not a lookup you go do somewhere else. You can answer with one, with a few, or with **all** — and "all" means every property on *that* connection, one call each, so the agent says what that will cost you in tool calls and waits for a yes before running them. The question itself doesn't cost you a tool call.

**Reads with exactly one property, site, or container are untouched.** If your login reaches a single GA4 property, nothing changes — the agent uses it and answers, exactly as before.

**Writes always confirm, even at one.** Search Console's `submit-url-for-indexing`, `submit-sitemap` and `delete-sitemap`, and Tag Manager's `create-tag`, `update-tag` and `update-variable` name their target back to you before they run. Tag Manager is a three-level hierarchy — account, then container, then workspace — and it asks one level at a time rather than presenting a list of everything at once.

This is the same idea as [one integration holding more than one account](/agent-skills/tools#marketing-stack-integrations-plus-and-above), one level deeper: first which account, then which property inside it.

**September 20, 2026**

Meta housing, employment, credit and politics campaigns no longer fail when you target outside your ad account's own country

## A Housing Campaign Can Run Somewhere Other Than Your Own Country

Meta requires a campaign in a Special Ad Category — **housing, employment, credit, or social issues, elections and politics** — to declare the country it runs in, separately from its targeting. ADSMCP sent the category but never the country, so Meta fell back to whatever country your ad account sits in and rejected the campaign the moment the targeting pointed anywhere else:

> The locations are not in the countries selected for Special Ad Categories

A US agency launching a housing campaign in Brazil hit that every time. ADSMCP now reads the country out of the campaign's own targeting and sends it alongside the category — ask for a housing campaign targeting Brazil and nothing else is needed.

It covers every create path that takes a special ad category — **`create_meta_image_campaign`**, **`create_meta_video_campaign`**, **`create_meta_carousel_campaign`**, and **`create_meta_catalog_campaign`** — plus **`update_meta_catalog_campaign`**.

Two cases still want a word from you. If you target only cities, regions, or ZIP codes and none of them names a country, there is nothing to read a country from: pass `special_ad_category_country` with the ISO codes yourself, such as `['BR']` or `['US', 'CA']`. Pass it too when the country the campaign is declared in genuinely differs from where it's targeted. ADSMCP never guesses one.

Campaigns with no special ad category are untouched — the field isn't sent at all.

**September 18, 2026**

ChatGPT Ads gets custom audiences from your own customer list, server-side conversion sending with hashed matching, conversion reporting, and ad-group auto-bidding

## Your Customer List Is Now A ChatGPT Ads Audience

Upload the people you already know and target them inside ChatGPT — or keep them out of a prospecting campaign. Twelve new tools cover the whole life of an audience: **`create_chatgpt_custom_audience`** to build one (empty, or seeded from a file you've uploaded to OpenAI), **`add_chatgpt_custom_audience_members`** and **`remove_chatgpt_custom_audience_members`** to change it, **`replace_chatgpt_custom_audience_members`** to swap the membership wholesale, and **`merge_chatgpt_custom_audiences`** to combine up to 64 of them into one.

Give the agent emails, phone numbers, identifiers you've already hashed, or Google Advertising IDs. Building an audience is asynchronous, so the tools hand back an operation you can watch with **`get_chatgpt_custom_audience_operation`** — and the agent polls until the audience is `ready` instead of reporting a size it can't see yet.

Then target it. A campaign can include audiences and exclude audiences, and an ad group can bid **0.1× to 10×** for one, so your highest-value list pays up without a separate campaign. Including an audience or bidding on it needs roughly 25,000 matched users; excluding one has no minimum. Size comes back as OpenAI's matched-user range — that is the only number OpenAI publishes, and ADSMCP won't invent a precise one.

## Conversions You Send Yourself, And View-Throughs Kept Apart

**`send_chatgpt_conversion_event`** posts a real conversion through the Conversions API — the path that survives ad blockers and the cross-device journeys a pixel misses. Send the event type, its value and currency, an order id so OpenAI can de-duplicate against the pixel, and the customer fields that raise match rates: email, phone, name, external id, country, city, region, postal code, IP, user agent, Google Advertising ID.

Raw emails, phone numbers, and names are **SHA-256 hashed at the point of the call**. The plain values never reach ADSMCP's backend and are never written to your tool-call history; the response reports which match keys were used, never what they were. Values are whole minor units — 2599 for \$25.99 — and a decimal is rejected rather than quietly truncated. Ask for a dry run and nothing is sent.

**`get_chatgpt_conversion_insights`** reads the results back by campaign, ad group, or ad, split by country or device on request. View-through conversions get their own line and are never folded into the total, so a view is never counted as a click.

## Auto-Bidding, Surfaces, And URLs That Tag Themselves

Ad groups now carry a bid strategy. Keep `fixed_bid` and set the number yourself, or hand it over with `maximize_clicks` or `maximize_conversions` — each of which needs a matching campaign bidding type, checked before the request is sent rather than after OpenAI rejects it.

Three smaller things that were missing:

* **Surface targeting.** Restrict a campaign to `ios_app`, `android_app`, `desktop_web`, or any mix, instead of running everywhere.
* **One query string for every landing page.** Set `utm_source=chatgpt&utm_campaign={campaign_id}` on the campaign; `{campaign_id}`, `{ad_group_id}`, `{ad_id}`, and `{ad_account_id}` are filled in when the ad serves.
* **Lists you can actually search.** Campaigns, ad groups, ads, pixels, and event settings all take a free-text search, a status filter, a sort, a date range, and paging — and report *3 of 41* rather than handing back an empty result that reads like an empty account. On ads the search covers the copy itself.

Targeting a campaign now has five sides — locations in and out, audiences in and out, and surfaces. Change one and the other four stay exactly as they were; if the agent can't read your current targeting to merge a change into it, it refuses rather than guessing.

Microsoft Advertising is no longer read-only — create and edit campaigns, ad groups, ads, keywords, budgets, bid strategies, extensions, Performance Max asset groups and targeting from your assistant

## Your Bing Account Is Something You Can Change Now

The launch note two days ago said creating and editing Microsoft campaigns weren't live. They are now. Every control you can create on Microsoft Advertising, you can also edit — campaign down to a single device bid adjustment — without opening the Microsoft interface.

Ten edit tools, one per layer:

* **`update_microsoft_campaign`** — name, budget, bidding scheme, languages, time zone, URL tracking, dates, and status.
* **`update_microsoft_ad_groups`** — name, status, CPC/CPM/CPV/mCPA bids, bidding scheme.
* **`update_microsoft_ads`** — status, and the creative on responsive ads: headlines, descriptions, long headlines, images, videos with pinning, paths, and URLs.
* **`update_microsoft_keywords`** — match type, status, and per-keyword bid.
* **`update_microsoft_budgets`** and **`update_microsoft_bid_strategies`** — the shared budget library and portfolio bid strategies.
* **`update_microsoft_asset_groups`** — Performance Max asset groups: business name, call to action, headlines, descriptions, images, videos, final URLs, paths, search themes, and dates.
* **`update_microsoft_ad_extensions`** — sitelink text and URLs, callout text, price rows, promotion details.
* **`update_microsoft_ad_group_criterions`** and **`update_microsoft_campaign_criterions`** — the bid adjustment and status on targeting you've already added, at ad-group or campaign level.

The create tools from the launch — campaigns of every type, ad groups, ads, keywords, extensions, Performance Max asset groups, audiences, and deep targeting — are live too.

## Edits Are Partial, With Two Places They Aren't

Pass the fields you want changed and everything else is left alone. Clearing a value is explicit: an empty string `""` clears a URL field, `0` detaches a shared budget or a portfolio bid strategy, and an end date on or after 2050-01-01 removes the end date.

Two exceptions worth knowing before you ask for an edit:

* **Creative lists replace.** Send headlines, descriptions, or images on an ad or an asset group and that whole list is replaced — omit it to keep what's there.
* **Ad extensions are all-or-nothing.** Microsoft deletes any field you don't send, so an extension edit has to carry the complete object. Ask your assistant to read the extension back with `list_microsoft_ad_extensions` first and it will.

A campaign's type can't change, and neither can the detail of a targeting criterion — the age range, device, or geo itself. Change a bid or pause it in place; to change what's targeted, delete it and add it again.

## Two Things That Can't Go Wrong Quietly

A Performance Max asset group edit refuses to replace a live asset list when an image or video fails to resolve, rather than emptying it. And extension and targeting edits never report an item as applied when Microsoft rejected it.

`list_microsoft_ad_extensions` also returns your account's extension library now — it came back empty for every account before, whatever was in there.

Performance reporting on Microsoft — spend, clicks, conversions — isn't live yet.

### Strategy-Aware Execution

Skills now read `STRATEGY.md` before executing — a persistent file where strategic decisions (AVOID, PREFER, CONSTRAINT, REQUIRE directives) survive across sessions:

* **Campaign creation** loads strategy directives at Step 0 and flags conflicts with research results
* **Keyword research** cross-references results against AVOID/PREFER directives
* **Performance review** flags "Strategy Drift" when campaigns violate active directives
* **Wasted spend** prioritizes campaigns violating strategy as waste sources
