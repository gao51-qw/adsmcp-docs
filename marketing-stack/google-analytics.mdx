## REST example

```http
POST /api/v1/tools/get_ga4_report/execute
{
  "platform": "google_analytics",
  "arguments": {
    "property_id": "properties/123456789",
    "date_range": "last_30d",
    "dimensions": ["sessionSourceMedium"],
    "metrics": ["sessions", "conversions"]
  }
}
```

## Tool order

GA4 does not change ads. Every tool below is read-only. Call these names. The older `google_analytics` tool is a dispatcher for the same reads.

1. `get_ga4_properties` lists properties the credential can open.
2. `get_ga4_metadata` lists dimensions and metrics for one `property_id`.
3. `get_ga4_report` runs one report. Pass `property_id`, `date_range`, `dimensions`, and `metrics`.
4. `get_ga4_realtime` reads current active users and top traffic sources for one `property_id`.
5. `batch_ga4_reports` runs several reports in one call. Pass `property_id` and `requests`.

`google_analytics` accepts `operation: "list_tools"` or `operation: "execute"`. Execute actions are `property_discovery`, `session_report`, `realtime_report`, and `ads_site_correlation`. `ads_site_correlation` compares paid campaign metrics with GA4 sessions and conversions. It does not write a campaign.

## Connect GA4

1. Open [Connections](https://adsmcp.si/dashboard/connections). Under **Google integrations**, choose **Connect** on **Google Analytics 4**.
2. Sign in with Google and allow read-only Analytics access (`analytics.readonly`). If you untick that permission, nothing is connected.
3. ADSMCP finds and lists every GA4 property the login can read. If it finds exactly one, that property is enabled automatically. With more, choose which properties your AI may use in the **Active accounts** card on Connections (any number, no plan cap). Reconnecting keeps your choices.
4. Call `get_connections_status`, then `get_ga4_properties`. Both show enabled properties only.

- A login that can read more than 500 properties is refused; nothing is connected. A login with no GA4 property is refused too.
- Each connection belongs to your ADSMCP login. Teammates connect their own.
- GA4 is its own MCP endpoint, separate from Google Ads. Connecting Google Ads does not connect GA4.
- A property that is connected but not enabled, or a call while no property is enabled, returns `error` `not_enabled` with a link to choose on Connections. Nothing is read from Google.
- Without a connection for the property, the tools return `{ "error": "no_data" }`. Do not invent a property id.

## Response fields

Each dedicated tool (`get_ga4_properties`, `get_ga4_report`, `get_ga4_realtime`, `get_ga4_metadata`, `batch_ga4_reports`) returns the adapter body. When the adapter is missing or returns nothing, the body is `{ "error": "no_data" }`.

`google_analytics` with `operation` `list_tools` returns `status` `ok`, `operations` (`property_discovery`, `session_report`, `realtime_report`, `ads_site_correlation`), `read_only` true, and `source` `services-mcp-google-analytics-local`. Properties are included when the adapter lists them.

Any other `operation` returns `status` `blocked`, `reason` `unsupported_google_analytics_operation`, and that same source. `execute` with an action outside those four names uses the same blocked body.

`execute` with a known action returns `status` `ok`, `action`, `property_id`, `date_range` (default `last_7d`), `read_only` true, `token_handling` `external_oauth_boundary`, `source` (the adapter source), and `data.rows` with the rows Google returned. An empty report returns `status` `ok` with empty `data.rows`. When no data comes back (no connection for the property, Google returned nothing, or the call failed), `execute` returns an error with `error` `no_data` and no rows. It never fills in example figures.
