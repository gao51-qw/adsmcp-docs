REST calls use the same tools, sign-in, quota and approval rules as MCP calls. The full per-tool reference is in the [API reference](/api-reference/introduction).

```text
POST https://mcp.adsmcp.si/api/v1/tools/{tool_name}/execute
```

- Tool list: `GET https://mcp.adsmcp.si/api/v1/tools`
- OpenAPI: `GET https://mcp.adsmcp.si/api/v1/openapi.json`
- Auth: `Authorization: Bearer sk_live_...` from [API Tokens](https://adsmcp.si/dashboard/api-tokens)

The dashboard host also forwards `https://adsmcp.si/api/v1/tools/...` to the same service.

## Example: a read

`analyze_search_terms` scores search-term rows you pass in.

```bash
curl -X POST https://mcp.adsmcp.si/api/v1/tools/analyze_search_terms/execute \
  -H "Authorization: Bearer $ADSMCP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "platform": "google",
    "arguments": {
      "account_id": "1234567890",
      "rows": []
    }
  }'
```

## Example: Google Analytics 4

```bash
curl -X POST https://mcp.adsmcp.si/api/v1/tools/get_ga4_report/execute \
  -H "Authorization: Bearer $ADSMCP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"platform": "google_analytics", "arguments": {"property_id": "properties/123"}}'
```

See [`get_ga4_report`](/api-reference/google-analytics/get-ga4-report) for the report arguments.

## Example: propose a change

A change returns a pending action. Nothing changes in the ad account until a person approves it on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page.

```bash
curl -X POST https://mcp.adsmcp.si/api/v1/tools/update_campaign_budget/execute \
  -H "Authorization: Bearer $ADSMCP_API_KEY" \
  -H "Idempotency-Key: budget-change-2026-11-03-001" \
  -H "Content-Type: application/json" \
  -d '{
    "platform": "meta",
    "arguments": {
      "campaign_id": "2384950123",
      "daily_budget": 2500
    }
  }'
```

Meta budgets default to the account currency's minor units (`2500` = 25.00); pass `"budget_unit": "major"` to send 25 instead. When the approved change runs, it is checked against your [spend cap](/safety#spend-cap).

## Response

```json
{
  "ok": true,
  "platform": "meta",
  "tool": "diagnose_campaign_health",
  "data": { "health_score": "needs_attention", "issues": [] },
  "error": null,
  "mcp_response": {}
}
```

On failure `ok` is `false` and `error` has `code`, `message` and `details`.

## Idempotency

Send `Idempotency-Key` on any request you might repeat. A completed request with the same key is replayed (`x-idempotency-replay: true`). A second request while the first is still running returns `409 idempotency_in_progress`.
