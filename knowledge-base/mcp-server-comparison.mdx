There are now several ways to let an AI client work on ad accounts over MCP. This page sets ADSMCP next to the ones people ask about most. It describes the other products as their own documentation described them in November 2026; check each vendor's current pages before you decide, because all of them are changing quickly.

## The short version

- **Use the platform's official server** when you work on one platform, your client supports it, and its scope fits: Google's is read-only; Meta's reads and writes, with no cross-platform view; TikTok's was announced in May 2026.
- **Use ADSMCP** when the work spans platforms, when every change must wait for a person on a dashboard, when you want an account-total spend cap and delete confirmation, or when a client or team needs shared dashboards, team seats on one subscription.
- The two are not exclusive. A client can keep Google's read-only server for Google Ads queries and call ADSMCP for the rest. See [ADSMCP and the Google Ads MCP](/google-ads-mcp).

What the official servers do not give you, and ADSMCP does: one login and one approval queue across platforms, a dashboard a non-technical person can approve from, shared read-only dashboards for clients, teams on one pool, and an audit trail of who approved what.

What ADSMCP does not give you that an official server might: the platform's newest API features on the day they ship, and a free, unmetered call budget.

Two other kinds of product come up in the same searches and solve a different job:

- **Reporting-only connectors** (for example Adzviser and Windsor.ai) read performance data into a chat or a spreadsheet and never change an account. If you only need reports, they are the simpler tool.
- **Open-source single-platform servers** (for example community Meta or LinkedIn servers on GitHub) are free and self-hosted. They run with your own API credentials, so the account risk and the maintenance are yours.

## How ADSMCP's approval model differs

Most servers rely on the AI client's own "allow this tool?" prompt. That prompt is answered by whoever is typing, in the chat, and it can be set to always allow. ADSMCP does not use it as the safety gate:

1. Every write tool stages a pending action; nothing reaches the platform when the tool returns.
2. A person opens the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page and approves or rejects it. `execution_mode` does not change this.
3. Budget changes and enables are checked against the account-total spend cap. Deletes need `confirm_delete: true` before they can even be staged.
4. A change that fails when it runs is not retried; it shows in the execution queue.

See [Safety model](/safety) for the full rules.

## Picking one

| You want to… | Use |
| --- | --- |
| Query one Google Ads account from a coding agent, free | Google's Ads MCP |
| Manage one Meta account from Claude or ChatGPT, and you are in Meta's beta | Meta's Ads MCP |
| Work across Google, Meta, TikTok, LinkedIn, Amazon, ChatGPT Ads or Microsoft Ads in one chat | ADSMCP |
| Let an agent propose changes but keep approval with a named person on a dashboard | ADSMCP |
| Give clients a live, no-login report link | ADSMCP shared dashboards |
| Pull reports into a spreadsheet and never change anything | A reporting-only connector |
