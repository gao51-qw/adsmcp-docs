description: "What to check when a client cannot log in, a platform is missing, a write is blocked, or Snap still appears."
---

Match the error you see. Do not resend a change until the cause is fixed; every change is staged again and needs a new approval on the dashboard.

## The client returns 401 or `invalid_token`

The API key is missing, revoked, or mistyped, or the OAuth session expired. Create a new key on [API Tokens](https://adsmcp.si/dashboard/api-tokens) (`sk_live_...`), or sign in again with OAuth. See [Authentication](/authentication).

## The client returns 401 `api_key_expired`

The key reached the expiry chosen when it was created (`expired_at` says when). Create a new key and replace it in the client's config.

## A call returns `permission_denied`

A read-only API key called a tool that needs a full key (any change, or managing monitors, schedules, rules or pending actions). Nothing was staged. Use a full key, or keep the read key for reads.

## Creating an API key returns `max_tokens_exceeded`

Your plan's limit of active keys is reached (Free 2, Plus 5, Pro 10, Max 20). Revoke a key you no longer use, or wait for one to expire.

## A call returns `ad_account_inactive`

The account is connected but not active on your plan. Choose it in the **Active accounts** card on [Connections](https://adsmcp.si/dashboard/connections), or upgrade. The refused call was not counted. See [Multiple accounts](/accounts#active-accounts).

## The sign-in page refuses the client's callback

ADSMCP accepts OAuth from Claude, ChatGPT, Cursor, VS Code and clients that use a `localhost` callback. Other clients, and custom schemes such as `cursor://`, need an API key. See [Authentication](/authentication#oauth).

## A call returns `approval_requires_dashboard`

The client tried to approve, execute or retry a pending action. Only a person can do that, on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page. Over MCP and REST you can list (`list_pending_actions`) and reject (`manage_action` with `decision: "reject"`).

## A delete is refused

`remove_*`, `delete_*` and `archive_*` tools (and their `batch_` forms) need `confirm_delete: true`. Without it nothing is staged. With it the delete is staged and still needs approval.

## An approved change fails with `spend_cap_exceeded` or `account_cap_exceeded`

The change would take the platform's total daily budget above your Max Daily Budget on the dashboard [Brand](https://adsmcp.si/dashboard/brand) page. Lower the requested budget, pause something else first, or raise the cap. `spend_cap_unreadable` or `account_budget_unreadable` means a budget could not be read, so the change was refused rather than allowed. See [Safety model](/safety#spend-cap).

## Google asks for a passkey

Google's own sign-in can ask for a passkey before it returns to ADSMCP. ADSMCP does not create that passkey and does not store it. Finish Google's prompt, confirm the account on [Connections](https://adsmcp.si/dashboard/connections), then call `get_connections_status`.

## The client connects, then every platform tool is empty

MCP login worked. The ad account grant did not. Open [Connections](https://adsmcp.si/dashboard/connections) and finish OAuth, then call `get_connections_status`. Google can also fail `get_google_api_readiness` when the manager account or the `adwords` grant is missing. TikTok has the same kind of check in `get_tiktok_api_readiness`.

## A Google create returns `google_adapter_unavailable`

The server does not have a usable Google Ads adapter for that call. The draft was not created. Fix the connection, then validate again. Do not send `create_search_campaign` in a loop.

## A call returns `quota_exceeded`

Your plan has used its tool calls (REST answers `402`). The `detail` says why:

| `detail` | What to do |
| --- | --- |
| `quota_exceeded` | The included calls are used. Wait for `period_end` or upgrade. |
| `overage_disabled` | Plus overage is off. Switch it on, or upgrade, on [Usage & Billing](https://adsmcp.si/dashboard/billing). |
| `overage_cap_reached` | Plus used its 150 calls and the $50 overage cap. Tools pause until the next billing period. |
| `overage_blocked` | An overage charge could not be completed, so overage is paused. The billing page shows the charge. |
| `payment_past_due` | A subscription payment is past due; overage is paused until it is paid. |
| `pool_exhausted` | The yearly pool is used. With overage on, the plan is re-billed 48 hours after the limit email; or use **Lift my limit now**. |
| `team_seat_inactive` | Your team uses more seats than its plan includes. Ask the owner to upgrade or free a seat. |

`get_usage_status` shows your usage. See [Pricing](/pricing).

## A billing action returns `team_owner_only`

Only the team owner can switch overage or lift the limit. See [Teams](/teams).

## A Search Console or Tag Manager call returns `ambiguous_site` or `ambiguous_gtm_*`

More than one site, account, container or workspace is connected and the call did not name one. It is not a connection problem: pick one from the list in the answer and call again.

## A call returns `quota_check_unavailable`

The quota service did not answer. Changes stop on purpose. Wait until `get_usage_status` works, then submit the change once.

## The campaign was created and is not spending

Creates stay paused, and TikTok ad groups are created disabled. `verify_google_campaign_is_live` and `get_amazon_moderation` only report status. Turning a campaign on is a separate change that needs approval on the dashboard. See [Approvals](/approvals).

## A comparison refuses to recommend a budget

`STRATEGY.md` is missing a KPI the workflow needs. Run `/adsmcp:setup`. The agent will not fill in a CPA, ROAS, CTR, or budget.

## Snap still shows up

Snap Ads are withdrawn. There are no Snap tools, no Snap connection on Connections and no Snap sign-in. The old Snap endpoints are gone, and what an old address answers depends on the host:

- `https://mcp.adsmcp.si/api/mcp/snap-ads` answers HTTP `501` with `error` `not_implemented` and a message that there is no MCP endpoint for snap-ads and that `get_connections_status` lists the supported platforms.
- `https://adsmcp.si/api/mcp/snap-ads` no longer exists (HTTP `404`).
- The `snap-ads.mcp.adsmcp.si` host is no longer served.

Nothing is sent to Snap from any of them. Remove the Snap endpoint from your client configuration. Older Snap cards in [Knowledge Studio](/knowledge-studio) stay readable, but no new ones can be created.

## Where to look next

Call `get_recent_errors` or `get_request_trace` to read your own recent errors. `why_did_this_fail` explains one trace. Admins see every user's events and can also open [Diagnostics](https://adsmcp.si/dashboard/diagnostics). The other read-only helpers are on [Diagnostic tools](/diagnostics). Send [support](/support) the tool name and the `reason`. Leave the token out.
