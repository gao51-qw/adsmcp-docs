title: "Muse"
description: "Connecting Muse to ADSMCP requires an API key header."
---

There is no ADSMCP connector listing in Muse.

ADSMCP does not accept Muse's OAuth sign-in, so use an API key.

Create an API key on [API Tokens](https://adsmcp.si/dashboard/api-tokens) first (it starts with `sk_live_`). Keep it in the client's config or an environment variable, never in a chat message.

## Add the server

In Muse's MCP or connector settings, add a remote (HTTP) MCP server:

| Setting | Value |
| --- | --- |
| Name | `adsmcp` |
| URL | `https://mcp.adsmcp.si/mcp` |
| Header | `Authorization: Bearer sk_live_...` |

If Muse cannot send a custom header to a remote MCP server, it cannot connect to ADSMCP directly. If the client can only start local (STDIO) servers, use the [STDIO proxy](/mcp-setup#stdio-proxy) instead.

## After you connect

1. Ask: *"Call get_connections_status and tell me which ad platforms are connected. Do not change anything."*
2. If a platform is missing, connect it on [Connections](https://adsmcp.si/dashboard/connections).
3. Ask for a read, such as last week's performance, before asking for changes.

Every change the client proposes is staged as a pending action. Approve or reject it on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page; the client cannot approve it. The client runs on your own AI model and plan, and each ADSMCP tool call counts against your [ADSMCP plan](/pricing).
