Performance Max uses the Google Ads connection. See [Google Ads](/ad-platforms/google-ads).

## Order

1. `get_connections_status` and `get_google_ads_accounts`.
2. `get_google_ads_pmax_campaigns` lists existing Performance Max campaigns (`id`, `name`, `status`, `type`; `limit` defaults to 25, max 100). `get_google_search_theme_ideas` suggests search themes; it does not add them.
3. `validate_google_pmax_asset_group` checks the final URL, headlines, long headlines, descriptions, marketing images, square images, logos and business name.
4. The dashboard [PMax validation playbook](/playbooks) stops at that validation.
5. `create_google_pmax_campaign` stages a paused campaign for approval.
6. `create_google_pmax_asset_group` stages one asset group (created `PAUSED`) for a campaign that already exists. Required arguments are `account_id`, `campaign_id`, `name`, `final_urls` and `assets`; each asset needs `asset_resource_name` and `field_type`.
7. If brand guidelines are on, `add_google_pmax_campaign_logo` stages the logo and business name at campaign level.
8. `enable_google_campaign` is a separate change that also needs approval, and is checked against the [spend cap](/safety#spend-cap). The creates above do not turn the campaign on.

Every call is staged, whatever `execution_mode` says: the response is `status` `approval_required` with `requested_action`, `queue_id`, `persisted` `true` and `source` `services-mcp-queue`. If the queue cannot store it, the response is `status` `stage_failed` and nothing is staged. A person approves the pending action on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page; only then does ADSMCP call Google. If Google rejects the approved change, the failure is shown on the approval item and is not retried.

## Asset check

`validate_google_pmax_asset_group` returns `status` `valid` or `blocked`, plus `errors`, `warnings`, `requirements`, and `source` `services-mcp-google-validation`. The check does not create a campaign. An omitted `daily_budget` is checked as 10.

| Field | Rule |
| --- | --- |
| `final_url` | HTTPS URL. |
| `daily_budget` | At least 10. |
| `headlines` | 1–5 items, 30 characters each. |
| `long_headlines` | 1–5 items, 90 characters each. |
| `descriptions` | 1–5 items, 90 characters each. |
| `marketing_images` | At least one landscape image near 1.91:1. |
| `square_marketing_images` | At least one square image. |
| `logos` | At least one logo. |
| `business_name` | Required, 25 characters maximum. |

`marketing_images`, `square_marketing_images`, and `logos` on this check are arrays of objects. A string is not counted. Landscape and square use the same width-to-height test as [Google Display](/ad-platforms/google-display). `logos` only requires one object. It does not check aspect ratio. When `headlines`, `descriptions`, or `long_headlines` has exactly one string, `warnings` includes that field name followed by ` is at minimum coverage; add variants for testing.` The warning follows the count, so it is also returned when `status` is `blocked`. When `errors` is empty, `status` stays `valid`.

## Create fields

The published schema requires `account_id`, `name`, and `budget_micros`. `budget_micros` must be a positive integer. Unless `validate_only` is true, `asset_group` must be an object. The adapter error text is `asset_group is required for Performance Max creation`.

| Argument | Use |
| --- | --- |
| `target_roas` | A positive value selects maximize conversion value with that target. It takes priority over `target_cpa_micros`. |
| `target_cpa_micros` | A positive value selects maximize conversions with that target CPA when `target_roas` is absent. |
| `final_urls` | Final URLs used when the asset group does not supply its own. |
| `asset_group` | `name`, `final_urls`, and `assets`. Each asset needs `asset_resource_name` and `field_type`. The asset group is created `PAUSED`. |
| `brand_guidelines_enabled` | When true, `LOGO`, `LANDSCAPE_LOGO`, and `BUSINESS_NAME` stay off the asset group. `business_name` is sliced to 25 characters and attached on the campaign with `logo_asset_resource_name` and `landscape_logo_asset_resource_name`. |
| `execution_mode` | Accepted for compatibility. It never skips approval: the call is always staged. |
| `validate_only` | When true, the mutate is validate-only and `asset_group` may be omitted. |
| `login_customer_id` | Manager account id when the call needs one. |

With neither target set, the campaign uses maximize conversions with an empty target. Channel is `PERFORMANCE_MAX` and campaign status is `PAUSED`.

## After approval

When the approved create runs, the campaign is created `PAUSED` with its budget and, when you passed one, its asset group. If Google rejects it, the reason (for example `google_adapter_unavailable` or `no_connection`) is shown on the approval item.

## Campaign logo

`add_google_pmax_campaign_logo` attaches brand assets to a campaign that already exists. The schema requires `account_id` and `campaign_id`. Optional fields are `business_name`, `logo_asset_resource_name`, `landscape_logo_asset_resource_name`, `execution_mode` (accepted, but the call is always staged) and `login_customer_id`.

When `business_name`, `logo_asset_resource_name`, and `landscape_logo_asset_resource_name` are all empty, the adapter throws `business_name or logo_asset_resource_name is required` and does not call Google. That throw is not turned into a `blocked` body. A missing `account_id` or `campaign_id`, or a mutate that returns nothing, returns `status` `blocked`, `reason` `no_connection`, and `source` `services-mcp-google-adapter`.
