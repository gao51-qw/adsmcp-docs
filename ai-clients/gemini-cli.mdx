## Add the server (OAuth)

```bash
gemini mcp add --transport http --scope user adsmcp https://mcp.adsmcp.si/mcp
```

Start `gemini`, run `/mcp` and sign in to `adsmcp` when asked. Gemini CLI receives the sign-in on a `localhost` callback, which ADSMCP accepts, so no API key is needed.

## Or use an API key

Create a key on [API Tokens](https://adsmcp.si/dashboard/api-tokens) (it starts with `sk_live_`) and add ADSMCP to `~/.gemini/settings.json` (or a project's `.gemini/settings.json`). Keep the key in the config or an environment variable, never in a chat message:

```json
{
  "mcpServers": {
    "adsmcp": {
      "httpUrl": "https://mcp.adsmcp.si/mcp",
      "headers": { "Authorization": "Bearer sk_live_..." }
    }
  }
}
```

If the client can only start local (STDIO) servers, use the [STDIO proxy](/mcp-setup#stdio-proxy) instead.

## ADSMCP extension

The `adsmcp` Gemini CLI extension bundles the MCP server, a `GEMINI.md` context file, 14 [skills](/agent-skills) and five commands: `/adsmcp:setup`, `/adsmcp:performance-review`, `/adsmcp:write-ad-copy`, `/adsmcp:wasted-spend` and `/adsmcp:campaign`. It is not in the Gemini CLI extension gallery yet (coming soon). From a checkout of the ADSMCP repository:

```bash
gemini extensions install ./plugins/gemini/adsmcp
```

Restart Gemini CLI, run `/mcp`, and sign in to `adsmcp` when asked. See [Workflows](/workflows) for what each command does.

## After you connect

1. Ask: *"Call get_connections_status and tell me which ad platforms are connected. Do not change anything."*
2. If a platform is missing, connect it on [Connections](https://adsmcp.si/dashboard/connections).
3. Ask for a read, such as last week's performance, before asking for changes.

Every change the client proposes is staged as a pending action. Approve or reject it on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page; the client cannot approve it. The client runs on your own AI model and plan, and each ADSMCP tool call counts against your [ADSMCP plan](/pricing).
