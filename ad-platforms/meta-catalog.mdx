Catalog ads use the Meta connection. The OAuth grant includes `catalog_management`. See [Meta Ads](/ad-platforms/meta-ads).

## Read the catalog

1. `get_connections_status`, then `get_ad_accounts`.
2. `get_meta_product_catalogs`, `get_meta_product_sets`, and `get_meta_creative_variants` each return `status` `unavailable`, `source` `adapter-unavailable`, `reason` `unsupported-capability`, and an empty `product_catalogs`, `product_sets`, or `variants` array. A string `account_id` is echoed. These calls do not read the catalog.

## Validate before a catalog ad

`validate_meta_catalog_ad_draft` is a read. It blocks the draft when any of these fail:

- `account_id`, `catalog_id`, and `product_set_id` are missing.
- `destination_url` is not an `https` URL.
- `daily_budget` is not a number of at least 5.
- `campaign_objective` is not `OUTCOME_SALES` or `PRODUCT_CATALOG_SALES`.
- `execution_mode` is not `paused` or `approval_required`.

A missing `creative` object is a warning. The draft can still be `valid`. The later create requires `creative`. A passing draft returns `ok` true and `status` `valid`. A failing draft returns `ok` false and `status` `blocked`, with `errors`, `warnings`, and `safety.approval_first` true.

## Create

`create_meta_product_set` needs `catalog_id`, `name`, and `filter`. It does not create the ad. Approving it returns `ok` false and `reason` `unsupported_meta_write`. `name` and `filter` are not posted to the product-set edge.

`create_meta_catalog_ad` needs `account_id`, `catalog_id`, `product_set_id`, `ad_set_id`, `name`, and `creative`. The call waits in [Approvals](/approvals). If the queue is unavailable, the result is `approval_queue_required`. Approving the queued call returns `ok` false and `reason` `unsupported_meta_write`. `catalog_id`, `product_set_id`, and `creative` are not posted to Graph.

`execution_mode` on these writes is `paused` or `approval_required`. Other values are rejected. Enabling the campaign is `enable_campaign`, and that is a separate approval.

## Dynamic creative

`validate_meta_creative_assets` is a read. When `dynamic_creative` is true, it requires at least two titles, one body, and one call to action. Every title must be 255 characters or fewer. A body longer than 500 characters is a warning. The asset set also needs one image of at least 600 by 600 with an `https` URL, or one video of at least 1 second with an `https` URL or a `video_id`. The read returns `ok`, `status` `valid` or `blocked`, `errors`, `warnings`, and `asset_counts` for titles, bodies, images, videos, and call to action types. It does not rewrite the text.

`create_meta_dynamic_creative` is an approval-gated write. It needs `account_id`, `page_id`, and `asset_feed_spec`. The approved post goes to the ad creative edge and sends `name`, `object_story_spec`, and `asset_feed_spec` when those fields are present. Object values are JSON-stringified. The post does not set `PAUSED`, and it does not send `page_id` or `degrees_of_freedom_spec`. This server does not cut titles or bodies on that create. `get_meta_creative_variants` is the unavailable read in the catalog section above.
