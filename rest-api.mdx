REST calls use the same tools, sign-in, quota and approval rules as MCP calls. The full per-tool reference is in the [API reference](/api-reference/introduction).

```text
POST https://mcp.adsmcp.si/api/v1/tools/{tool_name}/execute
```

- Tool list: `GET https://mcp.adsmcp.si/api/v1/tools`
- OpenAPI: `GET https://mcp.adsmcp.si/api/v1/openapi.json`
- Auth: `Authorization: Bearer sk_live_...` from [API Tokens](https://adsmcp.si/dashboard/api-tokens)

The dashboard host also forwards `https://adsmcp.si/api/v1/tools/...` to the same service, and exposes the quota and idempotency headers to allowed browser origins.

## Example: a read

`analyze_search_terms` scores search-term rows you pass in.

```bash
curl -X POST https://mcp.adsmcp.si/api/v1/tools/analyze_search_terms/execute \
  -H "Authorization: Bearer $ADSMCP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "platform": "google",
    "arguments": {
      "account_id": "1234567890",
      "rows": []
    }
  }'
```

## Example: Google Analytics 4

```bash
curl -X POST https://mcp.adsmcp.si/api/v1/tools/get_ga4_report/execute \
  -H "Authorization: Bearer $ADSMCP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"platform": "google_analytics", "arguments": {"property_id": "properties/123"}}'
```

See [`get_ga4_report`](/api-reference/google-analytics/get-ga4-report) for the report arguments.

## Example: propose a change

A change returns a pending action. Nothing changes in the ad account until a person approves it on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page.

```bash
curl -X POST https://mcp.adsmcp.si/api/v1/tools/update_campaign_budget/execute \
  -H "Authorization: Bearer $ADSMCP_API_KEY" \
  -H "Idempotency-Key: budget-change-2026-11-03-001" \
  -H "Content-Type: application/json" \
  -d '{
    "platform": "meta",
    "arguments": {
      "campaign_id": "2384950123",
      "daily_budget": 2500
    }
  }'
```

Meta budgets default to the account currency's minor units (`2500` = 25.00); pass `"budget_unit": "major"` to send 25 instead. When the approved change runs, it is checked against your [spend cap](/safety#spend-cap).

## Response

```json
{
  "ok": true,
  "platform": "meta",
  "tool": "diagnose_campaign_health",
  "data": { "health_score": "needs_attention", "issues": [] },
  "error": null,
  "mcp_response": {}
}
```

On failure `ok` is `false` and `error` has `code`, `message` and `details`. A tool that answers an error itself (for example GA4 `no_data`, or `not_enabled` for an item you have not enabled) also has `ok` `false`: `error.code` is the tool's code, `error.message` its message, `data` keeps the tool's output, and the HTTP status stays `200`.

A counted call also carries a top-level `quota` block (next to `data`, never inside it):

```json
"quota": { "used": 42, "limit": 10000, "tier": "pro", "period_end": "2026-12-01", "bonus_remaining": 0 }
```

## Quota

Every counted call returns these headers (and the same numbers in `quota`):

| Header | Value |
| --- | --- |
| `X-Quota-Used` | Calls made this UTC month. |
| `X-Quota-Limit` | The monthly [fair-use limit](/pricing#fair-use-limits) (10,000). |
| `X-Quota-Tier` | `pro` with a subscription (`free` without one). |
| `X-Quota-Period-End` | The UTC date the monthly count restarts (the 1st of next month). Left out when it cannot be read. |
| `X-Quota-Bonus-Remaining` | Always `0`: bonus calls belonged to earlier pricing. Kept so existing clients do not break. |

The daily limit is not in the headers; `get_usage_status` shows it. Plans with overage no longer exist, so the `X-Quota-Overage-*` headers are not sent.

The numbers are the ones on [Usage & Billing](https://adsmcp.si/dashboard/billing). Calls that are not counted (see [Pricing](/pricing#what-a-tool-call-is)) carry no quota headers.

**Over a limit,** the REST API answers `402` with `ok: false`, `reason: "quota_exceeded"`, `error`, and a `quota` block that adds `detail` (`free_limit_reached`, `subscription_required`, `daily_limit_reached`, `monthly_limit_reached` or `team_seat_inactive`) and `upgrade_url` (your billing page). Do not retry before `period_end`; the limit does not clear with backoff. MCP clients get the same refusal as a tool error instead of `402`.

## Errors

| Status | Reason | Meaning |
| --- | --- | --- |
| `401` | `invalid_token` | The key is missing, unknown or revoked. |
| `401` | `api_key_expired` | The key expired (`expired_at` says when). Create a new key. |
| `402` | `quota_exceeded` | The free allowance (30 a month) or a fair-use limit is reached, or a team owner has no subscription. See above. |
| `403` | `permission_denied` | A read-only key called a tool that needs a full key. Nothing was staged. |
| `403` | `ad_account_inactive` | The account you named is connected but not active. Not counted. See [Multiple accounts](/accounts#active-accounts). |
| `409` | `idempotency_in_progress` | The same `Idempotency-Key` is still running. |
| `503` | `quota_check_unavailable` | The quota service did not answer; changes are refused, reads continue. |

## Idempotency

Send `Idempotency-Key` on any request you might repeat. A completed request with the same key is replayed (`x-idempotency-replay: true`). A second request while the first is still running returns `409 idempotency_in_progress`.
