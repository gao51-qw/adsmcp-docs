An ad ops agent is the five workflows plus a schedule. [Agent Studio](/agent-studio) shows whether the tenant is ready. A ready row does not enable a campaign.

## What you give it

1. A plain-language goal, such as "keep CPA under the target in `STRATEGY.md`."
2. Connected accounts and the account ids. See [Set up a project](/set-up-a-project).
3. A cadence from [Scheduled cadence](/scheduled-cadence): a weekly brief, a monitor, or an automation rule.

## What it does on each run

1. Load `CLAUDE.md` and `STRATEGY.md`.
2. Call `get_connections_status`.
3. Read the platforms in scope. `/adsmcp:performance-review` builds the scorecard. `/adsmcp:wasted-spend` flags spend that misses the targets.
4. Return findings. A suggested pause, budget change, or enable is a Pending Action.

A person approves or rejects that action on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page; the agent can only list or reject it. See [Approvals](/approvals). `resume_workflow_after_approval` is always refused over MCP and REST with `approval_requires_dashboard`. After the approval, start a new request that reads the result.

The admin Watch Agent cron runs about every 15 minutes and calls `generate_performance_brief` for each connected account. A normal brief has recommendation text and no `signals` array, so that cron does not file a Pending Action from the brief. The command you named still runs when you invoke that workflow.

## Ready and one scan

[Agent Studio](/agent-studio) marks Watch Agent ready when the tenant has at least one usable connection, one active API token, and a live remote MCP endpoint. That ready flag means the scan can run. A ready row does not enable a campaign.

The MCP scan reads `target_roas`, `max_cpa`, `min_ctr`, and `max_daily_spend`, then the connected platforms. Missing strategy returns `success` false and `reason` `strategy_missing`. Incomplete targets return `success` false, `reason` `strategy_incomplete`, and `missing_kpis`. No connected platform returns `success` false and `reason` `no_platforms`. A finished scan returns `success` true, `signals_detected`, `actions_generated`, `platforms_checked`, and `duration_ms`. The budget-action step receives an object where the builder expects an array, the error is caught, and that step does not file a Pending Action.
