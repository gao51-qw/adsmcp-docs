A tool performs one operation. A **skill** is a short instruction file that tells your AI client which ADSMCP tools to call, in which order, and when to stop for approval. Skills run on your own AI model; ADSMCP supplies the tools and data. You do not need skills to use ADSMCP: every tool works without them.

Every skill carries the same rules:

1. Call `get_connections_status` before any platform tool.
2. Every change is staged as a pending action. Only a person approves it, on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page or in the confirm dialog of an [allowed AI client](/approvals#approving-in-your-ai-client). Over MCP the agent can view or reject; approving, executing and retrying are refused with `approval_requires_dashboard`.
3. Creates are paused or drafts. Enabling is a separate approved change.
4. Budget changes and enables are checked against the account-total [spend cap](/safety#spend-cap).
5. `remove_*`, `delete_*` and `archive_*` tools (and their `batch_` forms) need `confirm_delete: true`.
6. Failed changes are not retried. Ids are strings. Numbers come from tool results only, never invented.

## The skills

The skills use the open Agent Skills format (a folder with a `SKILL.md`), which Claude Code, Cursor, Gemini CLI, Codex and OpenClaw read.

| Skill | What it covers |
| --- | --- |
| `adsmcp-agent` | The safety contract above, and routing to the right skill. |
| `adsmcp-mcp` | How to reach a tool (platform routers, `search_tools`, `get_tool_schema`), which account id and budget unit each platform expects, quota, pending actions. |
| `adsmcp-google-ads`, `adsmcp-meta-ads`, `adsmcp-tiktok-ads`, `adsmcp-linkedin-ads`, `adsmcp-amazon-ads`, `adsmcp-chatgpt-ads` | One per platform: account discovery, validation and paused creates. |
| `adsmcp-launch` | Choosing a channel, validating a draft and staging a paused build. |
| `adsmcp-performance-review` | A read-only cross-platform scorecard against your own targets. |
| `adsmcp-optimize` | Wasted spend, negatives, placement exclusions and budget pacing, with every fix staged for approval. |
| `adsmcp-creative` | Copy written by your model within each platform's limits. |
| `adsmcp-docs` | Answers about ADSMCP from these docs. |
| `adsmcp-setup` | Local clients only: sets up a brand workspace folder (`CLAUDE.md`, `STRATEGY.md`, `MEMORY.md`). |

Microsoft Ads, Google Analytics 4, Klaviyo, Search Console and Tag Manager have tools but no dedicated skill; `adsmcp-agent` reaches them through `search_tools`.

## The five workflow commands

| Command | Returns |
| --- | --- |
| `/adsmcp:setup` | Checks `CLAUDE.md`, `STRATEGY.md` and `MEMORY.md`, calls `get_connections_status`, and says what to run next. It never invents a CPA, ROAS, CTR or budget. |
| `/adsmcp:performance-review` | A scorecard and the top three recommendations. A change becomes a pending action only after you pick one. |
| `/adsmcp:write-ad-copy` | Copy guidelines from `generate_ad_copy_ideas`; your model writes the variants. |
| `/adsmcp:wasted-spend` | Findings ranked by dollar impact; pauses, exclusions and budget changes are pending actions. |
| `/adsmcp:campaign` | A validated, paused campaign staged for approval. Enabling spend is a separate approval. |

The tool order of each command is on [Workflows](/workflows). Claude Code and the Gemini CLI extension use these `/adsmcp:` names. In Cursor, force a skill with `/adsmcp-<name>`. Other clients follow the same steps in plain language.

The Claude and Cursor plugins contain no hooks, scripts or executables, and no package stores a key. They talk only to `mcp.adsmcp.si` (and open `adsmcp.si` pages in a browser).

## Install from a checkout

From the root of an ADSMCP checkout:

```bash
# Skills (and the agent) for one client: claude, codex, gemini, cursor or openclaw
node ./bin/adsmcp-agent.mjs install --client=claude
```

Claude Code gets them in `~/.claude`; the other clients in `~/.agents` (`~/.agents/skills` is read by Codex, Gemini CLI and Cursor). It does not add the MCP server; do that with the client's own steps on [AI clients](/ai-clients).

The one-step installer can also run from the checkout. It checks every file against a SHA-256 list before writing, never asks for or stores a key, registers the MCP server through each client's own command (OAuth for Claude Code, Codex and Gemini CLI; an `ADSMCP_API_KEY` reference for OpenClaw; a printed snippet for Cursor), and leaves an existing `adsmcp` entry alone:

```bash
bash apps/web-next/public/install.sh --source-dir=apps/web-next/public/install/v1.1.0 --dry-run
```

Drop `--dry-run` to install; `--client=claude,codex` picks clients (default: detect installed ones). On Windows use `install.ps1` with `-SourceDir`, `-Client` and `-DryRun`. A hosted one-line installer at `adsmcp.si` is coming soon.

## The brand workspace

Skills keep context in local project files:

- `CLAUDE.md` holds voice, banned terms, CTA preferences and disclosures.
- `STRATEGY.md` holds target ROAS, max CPA, min CTR and spend limits.
- `MEMORY.md` holds confirmed outcomes from `record_learning`.

For a kit written from one Google Ads account's own data, see the [Prompt Engineering Playbook](/agent-skills/prompt-engineering-playbook).
