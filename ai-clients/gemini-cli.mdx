title: "Gemini CLI"
description: "Connect Gemini CLI to ADSMCP with an API key in settings.json."
---

Create an API key on [API Tokens](https://adsmcp.si/dashboard/api-tokens) first (it starts with `sk_live_`). Keep it in the client's config or an environment variable, never in a chat message.

## Add the server

Add ADSMCP to `~/.gemini/settings.json` (or a project's `.gemini/settings.json`):

```json
{
  "mcpServers": {
    "adsmcp": {
      "httpUrl": "https://mcp.adsmcp.si/mcp",
      "headers": { "Authorization": "Bearer sk_live_..." }
    }
  }
}
```

Start `gemini` and run `/mcp` to check that `adsmcp` is connected. If your Gemini CLI version signs in to MCP servers with OAuth through a `localhost` callback, that is accepted too. If the client can only start local (STDIO) servers, use the [STDIO proxy](/mcp-setup#stdio-proxy) instead.

There is no ADSMCP Gemini extension.

## Agent Pack (optional)

`node ./bin/adsmcp-agent.mjs install --client=gemini`, run from a checkout of the ADSMCP repository, checks the skill definitions in that checkout's `.gemini/settings.json` (`/skill adsmcp:setup` and the other four). See [Workflows](/workflows).

## After you connect

1. Ask: *"Call get_connections_status and tell me which ad platforms are connected. Do not change anything."*
2. If a platform is missing, connect it on [Connections](https://adsmcp.si/dashboard/connections).
3. Ask for a read, such as last week's performance, before asking for changes.

Every change the client proposes is staged as a pending action. Approve or reject it on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page; the client cannot approve it. The client runs on your own AI model and plan, and each ADSMCP tool call counts against your [ADSMCP plan](/pricing).
