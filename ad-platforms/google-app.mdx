App campaigns use the Google Ads connection. See [Google Ads](/ad-platforms/google-ads).

## Order

1. `get_connections_status` and `get_google_ads_accounts`.
2. `create_google_app_campaign` stages a paused shell for approval.
3. `enable_google_campaign` is a separate change that also needs dashboard approval. See [Approvals](/approvals).

This call does not create an asset group or a store-listing experiment.

## Required fields

| Field | Rule |
| --- | --- |
| `account_id` | Google Ads customer id. |
| `name` | Non-empty campaign name. |
| `budget_micros` | Positive integer. |
| `app_id` | Store app id, trimmed. An empty value throws `app_id is required`. |
| `app_store` | `GOOGLE_APP_STORE` or `APPLE_APP_STORE`. Any other value throws. |

Optional fields:

| Field | Rule |
| --- | --- |
| `target_cpa_micros` | Positive integer. Present: goal type `OPTIMIZE_INSTALLS_TARGET_INSTALL_COST` and a target CPA. Absent: goal type `OPTIMIZE_INSTALLS_WITHOUT_TARGET_INSTALL_COST`. |
| `execution_mode` | Accepted for compatibility. It never skips approval: the call is always staged. |
| `validate_only` | Forwarded on the Google mutate. |
| `login_customer_id` | Manager account id when Google requires one. |

The campaign status is `PAUSED`. The channel is `MULTI_CHANNEL` with subtype `APP_CAMPAIGN`.

## What the call returns

Every call is staged, whatever `execution_mode` says: the response is `status` `approval_required` with `requested_action`, `queue_id`, `persisted` `true` and `source` `services-mcp-queue`. If the queue cannot store it, the response is `status` `stage_failed` and nothing is staged. A person approves the pending action on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page; only then does ADSMCP call Google. If Google rejects the approved change, the failure is shown on the approval item and is not retried.

Read the JSON text of the result; see [MCP protocol](/mcp-protocol).
