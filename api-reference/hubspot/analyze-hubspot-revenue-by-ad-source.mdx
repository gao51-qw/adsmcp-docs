Closed-won HubSpot revenue and deal count by ad platform for a period, with the same period's ad spend for each ad platform the user has connected, so the AI can compare CRM revenue with spend (CRM-based ROAS). Fixed mapping from the contact's original source (HubSpot's paid search drill-downs hold the campaign and search term, not the engine, so for PAID_SEARCH and PAID_SOCIAL the network is the first match of: a click id in the contact's first page URL, its utm_source, its first referrer's host, the drill-down words): PAID_SEARCH with gclid / gbraid / wbraid, utm_source google or adwords, a google.* referrer or HubSpot's 'Auto-Tagged PPC' -\> Google Ads; PAID_SEARCH with msclkid, utm_source bing or microsoft, or a bing.* referrer -\> Microsoft Ads; PAID_SOCIAL with fbclid, facebook, instagram or meta -\> Meta; li_fat_id or linkedin -\> LinkedIn; ttclid or tiktok -\> TikTok; a paid source matching none -\> paid_unmatched; any other recorded source -\> other; none -\> unattributed. The table is not verified against a live portal: attribution_summary counts the deals outside the ad platforms so a miss is visible. Spend is read with the platforms' own report tools for the connected, active accounts (Google Ads, Microsoft Ads and TikTok for any period, LinkedIn for a period ending yesterday or earlier, Meta for 7, 14, 28, 30 or 90 days), within a 45 s time budget: a read that does not finish is reported unavailable (time_budget), never as zero. crm_roas is given only when the revenue and the spend are in one and the same currency; otherwise both amounts are returned with roas_unavailable (currency_mismatch, currency_unknown, no_spend, spend_incomplete, deals_truncated, not_connected, not_supported or period_not_supported). Never converts currencies. Charged as one call. Read-only.

**Platform:** HubSpot · **Type:** Read
