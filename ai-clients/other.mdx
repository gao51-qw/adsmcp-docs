Any MCP client can connect:

| Setting | Value |
| --- | --- |
| Name | `adsmcp` |
| URL | `https://mcp.adsmcp.si/mcp` |
| Transport | Streamable HTTP |
| Auth | OAuth if the client signs in through a `localhost` callback; otherwise `Authorization: Bearer sk_live_...` |

Create an API key on [API Tokens](https://adsmcp.si/dashboard/api-tokens) first (it starts with `sk_live_`). Keep it in the client's config or an environment variable, never in a chat message. A key in the URL query string is rejected.

If the client can only start local (STDIO) servers, use the [STDIO proxy](/mcp-setup#stdio-proxy) instead. Protocol details are on [MCP protocol](/mcp-protocol).

Clients without slash commands can still follow the [workflows](/workflows): ask for setup, a performance review, ad copy, a wasted-spend check, or a paused campaign in plain language.

## After you connect

1. Ask: *"Call get_connections_status and tell me which ad platforms are connected. Do not change anything."*
2. If a platform is missing, connect it on [Connections](https://adsmcp.si/dashboard/connections).
3. Ask for a read, such as last week's performance, before asking for changes.

Every change the client proposes is staged as a pending action. Approve or reject it on the dashboard [Approvals](https://adsmcp.si/dashboard/approvals) page; the client cannot approve it. The client runs on your own AI model and plan, and each ADSMCP tool call counts against your [ADSMCP plan](/pricing).
